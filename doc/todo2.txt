================================================================================
SOLUTION: Initialize Git Submodules in GitHub Actions Workflow
================================================================================

ROOT CAUSE:
The secp256k1 directory exists but is empty because git submodules are NOT
automatically initialized when GitHub Actions checks out the repository.

The error message indicates:
  "The source directory /home/runner/work/test/test/src/utils/secp256k1
   does not contain a CMakeLists.txt file."

This happens because the submodule directory is created but not populated.

FIX FOR GITHUB ACTIONS WORKFLOW:

Add a step to initialize submodules AFTER the checkout step:

```yaml
- name: Checkout code
  uses: actions/checkout@v4

- name: Initialize git submodules
  run: git submodule update --init --recursive
```

COMPLETE EXAMPLE WORKFLOW:

```yaml
name: CI Build

on: [push, pull_request]

jobs:
  build:
    runs-on: ubuntu-latest

    steps:
    - name: Checkout code
      uses: actions/checkout@v4

    - name: Initialize git submodules
      run: git submodule update --init --recursive

    - name: Install dependencies
      run: |
        sudo apt-get update
        sudo apt-get install -y cmake clang libssl-dev libboost-dev

    - name: Configure CMake
      run: |
        cmake -B build \
          -DBUILD_TESTS=ON \
          -DCMAKE_BUILD_TYPE=Debug \
          -DCMAKE_C_COMPILER=clang \
          -DCMAKE_CXX_COMPILER=clang++

    - name: Build
      run: cmake --build build -j$(nproc)

    - name: Run tests
      run: cd build && ctest --output-on-failure
```

ALTERNATIVE: Use actions/checkout with submodules parameter:

```yaml
- name: Checkout code with submodules
  uses: actions/checkout@v4
  with:
    submodules: recursive
```

This automatically runs `git submodule update --init --recursive` during checkout.

WHY THIS HAPPENS:
- Git submodules are NOT included in regular git clone by default
- GitHub Actions checkout action does NOT initialize submodules by default
- The .gitmodules file and submodule reference are checked out, but the actual
  source code in src/utils/secp256k1/ is not downloaded
- CMake then fails when trying to add_subdirectory() an empty directory

VERIFICATION:
After adding the submodule initialization step, the workflow should:
1. Successfully initialize secp256k1 submodule
2. CMake configure completes without errors
3. Build succeeds
4. Tests run successfully
